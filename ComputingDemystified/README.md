## 一句话

计算机术语不是理论，而是**某个资源瓶颈下的折中**；每个词都能还原成一张账单：
**为哪一项稀缺资源付账、合并或拆开了什么、核心能不能写成几行 `if`/`for`、最后由谁承担。**

## 这篇论文在做什么

面向 Agent 时代的读者：把 8 层、80 条高频术语逐条编码成《术语账本》，用"三问加一问"还原，
用六本专著的概念作分析坐标，给出三条结果、四条负面结果、一个 20 行 Agent、一条四周路径，
以及一节**还原论的边界**——祛魅不是否定，简单原理不等于简单工程。

## 三条结果

1. **名词比机制多**：80 条术语只落在 7×7 账格的 27 格里，最大一格 7 条。
2. **三角只管六成**：C-A-T 覆盖 51 条（64%）；29 条（36%）是纯资源置换，记在时间与容量轴上。
3. **可写性不是层的属性**：77/80 的核心能写成十行以内；硬件层 10/10 可写，网络与存储层反而更难写，
   上层"黑话"对应的是更大的工程量，不是更难的机制。

## 四条负面结果

- **F1** 还原解释机制，不预测行为。
- **F2** "跨主体"只是记账的伴随条件（83% 对 49%，OR=5.05，p=0.002；28 条例外）。
- **F3** 简单原理与简单工程之间隔着状态空间（O(1) 对 O(状态空间)）。
- **F4** 在涌现与提示注入上，还原给不出机制。

## 边界

- 八十条是**分层目的抽样**，不是计算机术语全集；文中所有比例（36% 无让出、96% 可写）均为样本内计数。
- 八十条术语由作者一人编码（第一轮 60 条，第二轮补 20 条；单编码者）：`bneck/swap/cat/impl` 四个字段带同一个人的判断习惯；
  `cross` 与 `cat` 同轮编码，存在循环论证风险；28 条例外（6+22）逐条列在正文 4.3 节。
- 等级是证据等级，不是重要性：A 规范/源码/可算，B 稳定共识，C 类比与判断。
- 还原解释机制，不预测性能数字；具体框架与 API 细节会过时，正文只讲机制。
- 不评价具体产品；不预测。
