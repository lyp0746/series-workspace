# 记忆的锚点：情景唤起、异构重建与日志裁决

**一个会自己发视频、会评论、会开直播的 Agent，为什么在几天之内就「死」了**

李毅芃 · 2026-10-26 · 工作论文（50 页，CC BY 4.0）

*The Anchor of Memory: Episodic Recall, Heterogeneous Reconstruction, and Log Adjudication in Agents*

---

## 一句话

2026 年那批「自己在动」的社交账号，第四到第七天安静下来。社区说「它记不住了」，本文说方向错了：**它们不是死于容量，是死于「不知道该信哪一条」**。给 Agent 装上「存残余、多线索、现场重建」的宫殿式记忆，再配一层只认日志的裁判——这套东西的名字叫**记忆的锚点**。

## 摘要

人类记忆不是「存全量、按索引读」，而是「存残余、多线索、现场重建」：情景带时间与地点（[13]），检索依赖编码时的情境（[14]），空间是最便宜的索引链（[15]），回忆是重建而非播放（[16][17]）。本文把这个机制拆成三层并审计：**书记员**（字段级硬日志，不由生成模型执笔）、**异构回忆者**（随机森林式：不同模型、不同参数、不同线索子集，各自独立重建）、**裁判**（只认锚点，无锚一律标 C）。

三个可复算的结果。**第一，现有 11 个记忆方案里没有一个同时具备「硬日志锚点 + 跨模型异构 + 带锚裁决」**；硬日志锚点拥有率仅 3/12，最成熟的四个底层方案（RAG、注意力、Hopfield、长窗口）全部没有锚点——**最缺的不是容量，是锚定**。**第二，投票只在参与者独立时有效**：单模型错误率 0.2、共源相关 0.7 时，11 个模型投票的错误率仍达 14%，只比单模型低 6 个百分点。**第三，失效与容量弱相关**：窗口满 2/12，而「检索噪声 + 摘要漂移」合计 5/12。

本文还解剖了那个「几天就死」的案例：四种死亡机制（窗口满、摘要漂移、检索噪声、成本超支）、六条「症状→机制→补丁→补丁也治不了」的映射、以及一个反例配置（窄域＋短记忆＋强规则，不需要情景记忆）。**对西藏口诵传经的投票类比，本文给出一条明确边界：经文有原典可对照，记忆没有——投票应决定「哪条重建路径更可靠」，不能决定「哪个记忆是真的」。** 十条命题：六条支持、一条部分、两条待测、**一条被自己撤回**（T9：该架构能把「几天」延长到「几周」——无实验）。
