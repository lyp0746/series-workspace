# 重建手册（这套东西怎么从源重出成品）

写给三个月后的自己。全部路径相对 `D:\0_Article`。

## 0 一页流程图

```
书九本    <书>/source/*.html ──┐
                               ├─► <书>/build_book.py --pdf ──► output/book.pdf
                               │   <书>/build_book.py --ereader --pdf ──► book-ereader.pdf
                               │   <书>/build_markdown.py ──► output/markdown/
                               │   <书>/build_epub.py ──► output/book.epub
                               │
论文十五  <论文>/source/paper.md ──► <论文>/<中文名>.md ──► generate_publication_suite.py ──► .html/.pdf
                               │
合集      <书>/source/*.html ＋ <论文>/<中文名>.md ──► 合集/build_collection.py ──► release/00/01-*.pdf
                               └─► 合集/rebuild_pmap.py（页码回填）──► 再建一遍
单行本    合集/单行本/*.md 或 .docx ──► build_zhongdao.py / build_sanwen.py ──► out/*.pdf
```

**因果方向是单向的**：源 → 分册 → 合集。任何改动都必须从最上游改起，否则下一次重建会被覆盖回去。
尤其是：`<论文>/source/paper.md` 是源，`<论文>/<中文名>.md` 是派生——只改派生文件，下次生成就没了。

## 1 环境

```bash
# 一次性：本地虚拟环境（已被 .gitignore 忽略）
uv venv .venv --python 3.12
uv pip install --python .venv/Scripts/python.exe \
    reportlab python-docx pymupdf pypdf markdown beautifulsoup4 lxml playwright
.venv/Scripts/playwright.exe install chromium      # 只装一次
```

两条渲染路线都要有：

| 用途 | 引擎 | 触发 |
|---|---|---|
| 书、粗码的 PDF | Chrome / Edge（`--headless=new --print-to-pdf`） | `build_book.py --pdf` |
| 论文 PDF、合集 PDF | Playwright 的 Chromium | `generate_publication_suite.py` / `build_collection.py` |
| 单行本 PDF | ReportLab（纯 Python，不依赖浏览器） | `合集/单行本/build_*.py` |

Playwright 版本与已装浏览器必须对得上（报 "Executable doesn't exist …chromium_headless_shell-XXXX" 就是版本漂了），
装一次 `playwright install chromium` 即可，不必回退版本。

## 2 一次完整重建（约 40 分钟）

```bash
cd D:\0_Article
.venv\Scripts\python.exe _rb.py papers      # 15 篇，约 90 秒
.venv\Scripts\python.exe _rb.py books       # 9 本 ×（印刷+电子+md+epub），约 5 分钟
cd 合集
..\.venv\Scripts\python.exe build_collection.py
..\.venv\Scripts\python.exe rebuild_pmap.py      # 按实际页码重算 _pages.json
..\.venv\Scripts\python.exe build_collection.py  # 再建一遍，让目录页码落到纸上
..\.venv\Scripts\python.exe rebuild_pmap.py      # 对比：与上一份一致 = 收敛
```

`_rb.py` 是一次性驱动脚本（跑完可删）；核心是那条**两遍 + 回填**的循环。

**收敛判据**：第二遍的 `_pages.json` 与第一遍逐字节相同。不同就再建一遍，直到相同。
内容增删导致总页数变化时，一般两遍就收敛；一次都没收敛过，说明 `rebuild_pmap.py` 的判定失效了（见 §3）。

## 3 踩过的坑（按代价排序）

### 3.1 目录页码回填：旧脚本会静默写成 0

旧的 `rebuild_pmap.py` 用「全文搜索 + 页面字数上限」找标题页。内容一变，探针就再也匹配不上，
而它**照样写盘**——结果 `_pages.json` 里九个卷页号只填了一个，其余为 0，总目录整排 `0`。
更阴的是它不报错。

现在的 `rebuild_pmap.py` 改成结构判定，并**带断言**：

- 卷封面／论文封面／章首页 = 该页规范化正文**以**「卷X」「论文X」「第N章」**开头**（不是包含）；
- 附录不用这条判据（附录小节页也会以「附录」开头），改为按源文件 `<h2>` 原文精确前匹配，
  并框在「本卷封面 → 下一卷封面」之间；
- 三类标题页数量必须等于 `VOLUMES`／`PAPERS`／`parts.json` 算出来的期望值，不等就 `assert` 失败。

判据从「包含」改成「开头」，是这件事唯一的关键。

### 3.2 全局替换会毁掉历史留痕

`archive/`、`versions/`、`release/` 里存的是**已发布快照**，批量替换必须白名单排除。
另外 `analysis/V*-RESTRUCTURE*.md` 里出现的「三十八章」是版本留痕，改了就没法回溯。

### 3.3 序号迁移要用占位符走两遍

旧号→新号是多对一的一团（十→九、九→十五、十一→十…），直接顺序替换会二次命中。
正确做法：先把所有旧串换成唯一的 `\x00i\x00`，再统一回填。
`_series/tools/fix_241125_errata.py` 就是这个写法，并且**幂等**——跑第二遍零改动。

### 3.4 各篇的编号状态可能不一致

那次迁移里，同构的强度、记忆的锚点、锚点的下限已经改成新号，其余六篇还是旧号。
所以**不能**按「全仓库替换」处理，只能按文件逐个声明映射。动手前先扫一遍每篇的自述行
（「本论文为系列第X篇工作论文」）判断它处在哪一代。

### 3.5 ReportLab 的中文排版

- **标点禁则**：reportlab 自带的 `ALL_CANNOT_START` 只收了日文半角标点，全角「；，：！？」不在里面，
  于是「；」会跑到行首。`合集/单行本/common.py` 顶部补了全角集合并打上 monkey patch。
- 它**不做**「不能行末」（开引号「“」可以停在行尾）。要彻底解决得自己预处理，代价大，先接受。
- 字间距用「空格模拟」（`" ".join(...)`），没有 `charSpace` 属性。
- 自定义 `Canvas` 里清掉预涂的底色 `self._code.clear()`，否则文末多一页空白。
- 页眉要在 `showPage()` 里画（此时才知道本页是不是章首页）。

### 3.6 「每部分填满一页」怎么调

只能量，不能猜。顺序是：先定**每页可用高度**（A4 − 上下边距 ≈ 244 mm），再按 `行数 × leading`
反推要删/加多少行。真正好用的旋钮只有四个：

1. 分节前的 `Spacer`（11 mm → 9 mm 就能挤出一整行）；
2. 标题下的 `Spacer`；
3. 正文字号 / leading（改动要整本验证，别只改一处）；
4. 字数——最后一个短句往往只溢出 1 行，把它并进前一段（如「客退而书之」并进答句）比删内容划算。

### 3.7 图版会制造半页空白

图片是高块，放不进当前页就整块跳页，前一页留下 40% 空白。
先算剩余空间再定图的大小：`max_h` 取「剩余高度 − 上下留白」。这台机器上 108 mm 宽、80 mm 高
刚好能塞进半页，132 mm 就会跳页。

### 3.8 docx 作为源

用 `python-docx` 的 `insert_paragraph_before`，并**沿用锚点段的样式**；不要新建样式。
Word 打开着的时候别写盘（`~$xxx.docx` 锁文件在旁边）。

### 3.9 只改等长短标题，仍要逐页 diff

「三十八章 → 三十九章」同为三字，理论上不引起断行。但重建后必须验证，方法是逐页取文本比对：
这次结果是 776 页对 776 页、只有第 4 页不同（目录首页），才敢说「只重印一页」。

## 5 合一版：把散文放进粗码前面（2026-11-25 新增）

需求：投递包（Zenodo）里是一本书，《得鹿梦鱼》作卷首；Downloads 里仍是两册分开。

**唯一正确的页码体例**：卷首用**罗马数字 i—xxvi**，正文保持**原阿拉伯页码**。
这样粗码的目录、索引、节号、表图号、144 条书签**一个字都不用动**。
反过来做（把粗码整体 +26 页）意味着：目录两遍回填、索引重算、书签全偏移——三处都容易错。

做法（`合集/单行本/make_combined.py`）：

1. `build_sanwen.py --no-cover --roman --out _sanwen_roman.pdf` → 26 页，i 起；
2. 现做一页总封面（宣纸版式，两字作「粗码」朱砂印）；
3. `pymupdf` 合并：封面 ＋ 卷首 ＋ 粗码（`from_page=1` 去掉粗码原封面）；
4. 书签手工搬：卷首 7 条 +1 页偏移；粗码全部 +26 页；再补两条一级节点「卷首」「粗码」；
5. `set_metadata` 写标题/作者，`save(garbage=3, deflate=True)`。

`CFG["cover_pages"]` 是关键开关：它为 0 时第 1 页就印页码、不画封面折角框。
页码公式：`body_no = page_no - cover_pages + folio_start - 1`。

**没做的**：电子阅读版（499×709）仍是单册——把它也合进去要按 499×709 重排散文，
属于另一件事。`.zenodo.json` 里已注明「印刷版 809 页（合一）、阅读版 975 页（单册）」。

## 6 往书里加一节：第 27 章 §27.7 的实操记录

目标：在 27.6 与 27.7 之间插入新节，旧的 27.7/27.8/27.9 顺移。

## 7 新公式要写成书的 `class="eq"`

别用 `text-align:center` 的纯文本凑——书里的公式是
`<div class="eq"><span class="body"><math display="block">…</math></span><span class="num">(27.2)</span></div>`，
编号右对齐。手写 MathML 虽然啰嗦，但两三条式子值得，否则一眼就看出不是一本书里的。
