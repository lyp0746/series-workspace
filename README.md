# 有限系统的取舍 · 系列工作区

**The Tradeoffs of Finite Systems — Series Workspace**

李毅芃（Li Yipeng）· 独立研究者 · 2026-11-12

---

九本书与十五篇工作论文，研究的其实是同一个问题：**一个有限的东西，怎样一边保持自己的样子，一边还能改变。**

这个仓库不是其中任何一本，而是它们共用的一套东西：**结构规范、校阅器、推理工具、十五篇论文的源文件，以及全部归档元信息。**
九本书各自有独立仓库（正文以 HTML 为权威来源），这里只放它们不装得下的部分。

**件数**：24 件（9 书 + 15 篇）+ 1 部合集。件数只由 `inventory.tsv` 决定。

## 一、这里有什么

| `_series/lint/` | **校阅器**：18 条在役规则（编号 r01–r24），一次跑完 24 件，输出 `REPORT.md`（当前 error 0 / warn 0）与工作账 |
| `_series/tools/` | 可重跑工具：章节合并与重编号、附录归并、PDF 书签、扉页插图、元信息同步、版式体检、引用抽检 |
| `_series/review/` | 2026-11 全系列审阅账（总报告、逐件报告、引用抽检、已执行的论文计划存档） |
| `_series/content/` | 校阅期间写的增补稿，可追溯 |
| 十五篇论文目录 | `source/paper.md` 为唯一正文源；`data/` 数据、`analysis/` 脚本、`assets/` 图件 |
| `_zenodo/` | 24 件 + 合集的归档登记（版本 DOI / 概念 DOI / 页数）与描述生成脚本 |

## 五、这套工具在防什么

校阅一部长达 100 万字的系列，靠记性一定会漏。这个仓库把"记性"换成了四条可执行的检查：

1. **骨架**：每章八段（主提问、场景、导论、机制、表图、反例、小结、一句话带走），缺一段 lint 就报。
2. **附录**：≤6 件；**单节正文 ≤1200 字**——附录是证据与工具，不是第二正文。
3. **编号**：一个序列一个词；章号冻结后只在重排窗口整体改；引用回写后逐条校验。
4. **账**：每一条主张都登记 A/B/C 与状态；对账篇把 126 条放在同一张表上。

`_series/lint/WORKLOG.md` 记着这套工具自己的事故与修复——包括一次正则表达式吃掉 280 行代码。**工具也上账。**
